# Mail Desk — 契約通知メール作成アプリ

Windows専用のPythonデスクトップアプリです。貼り付け・txt読み込みから契約通知メールの対象一覧を作り、内容を確認して従来版Outlookに下書きを保存、または送信します。

## 画面

左のメニューで入力・一覧確認・設定を切り替えます。一覧画面は、罫線付きの表を画面幅いっぱいに表示し、1人分の情報を各セル2行にまとめています。件数は下部に小さく表示します。確認済み・未確認の状態やチェック操作はありません。

| 列 | 1行目 | 2行目 |
|---|---|---|
| 対象 | 対象／除外 | 作成待ち・要修正などの状態 |
| 管理番号／承認状態 | 管理番号 | 契約承認状態 |
| 氏名・派遣元／メールアドレス | 氏名（派遣元） | 実際のToアドレス |
| 受入開始・終了 | 受入開始日 | 受入終了日 |
| 受入先情報 | 会社名／事業所名 | 部署名／業務名／チーム名 |

共通の件名・CCは表の上に表示します。個別編集で共通CCと異なる指定にした場合は、その行のメールアドレスの後にもCCを表示します。長い項目は省略せず、列幅を広げて横スクロールで読めるようにします。上下スクロール中も見出しは表示します。

宛先未登録、件名未設定、不正なメール内容、結果が不確定な処理など、問題がある行だけを着色します。問題を直すと色が消えます。正常な行と作成済みの行には状態による色を付けません。選択中の行は青い枠で表示します。上部の実行モード表示で下書き保存／送信を確認でき、一覧の「対象」列は1行目・2行目のどちらをクリックしても切り替えられます。

「本文・取り込み情報を表示」を押すと、選択したメールの詳細を別ウィンドウで開けます。個別編集した本文などを確認するときにも利用できます。「メール本文」「取り込み情報」のタブは、選択状態で大きさと表示領域が変わらないようにしています。

現在の一覧画面は、上の表のとおり罫線付き・2行表示です。`docs/previews/review.png` は旧表示の参考画像です。現在のコードから画面を撮影する方法は末尾の「検証」を参照してください。

[入力画面](docs/previews/input.png) / [設定画面](docs/previews/settings.png)

同梱の設定画面画像は旧版の参考です。現在は「社員情報CSV」「CSVを読み込む」「社員情報を確認」を表示します。

画像はサンプルデータで実際のPython/Tk画面をLinux上で起動・撮影したものです。Windowsではフォントなどの表示に多少の差があります。画像の件名は表示例で、実際の初期値は空欄です。

## 導入と起動

1. Windowsに **Python 3.11以降**をインストールします。Python Launcher（`py`コマンド）も有効にしてください。
2. **従来版Outlook（classic）**でメールアカウントを設定し、通常のメール作成・送信ができる状態にします。
3. このフォルダーを展開し、初回に `setup.bat` をダブルクリックします。パッケージの取得にはインターネット接続が必要です。
4. `start.bat` をダブルクリックして起動します。

旧版から更新する場合は、追加されたドラッグ読み込み用パッケージを導入するため `setup.bat` を再実行してください。EXE版は `build_exe.bat` で作り直してください。

コマンドで導入する場合:

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py
```

新しいOutlookは対象外です。送信には従来版Outlookの既定アカウントを使用します。Outlookや組織の設定によっては、操作時に確認ダイアログが表示される場合があります。

## 「No module named tkinterdnd2」と表示された場合

起動に使ったPythonにドラッグ読み込み用のライブラリが入っていません。**アプリのフォルダーで `setup.bat` を再実行し、`start.bat` から起動してください。** `main.py` のダブルクリックでは別のPythonが使われることがあります。

`start.bat` は必要なライブラリを確認し、不足していればアプリ専用の `.venv` へ `requirements.txt` のパッケージを導入してから起動します。この修復時はインターネット接続が必要です。インストールや確認に失敗した場合は起動せず、エラーを表示します。

手動で修復する場合は、アプリのフォルダーの**コマンドプロンプト**で次を実行します。

```bat
.venv\Scripts\python.exe -m pip install -r requirements.txt
start.bat
```

別のPythonから実行したい場合は、エラー画面に表示される、そのPythonのパスを使ったコマンドを実行してください。単に `pip install` だけを実行すると、別のPythonへ入る場合があります。

EXE版の場合はPythonへの追加インストールでは解消しません。ZIPを展開し直してEXEと `_internal` フォルダー全体を揃えてください。ソースが古い場合は最新版で `build_exe.bat` を実行し、作り直したonedirフォルダー全体を配布してください。

## onedir形式のEXEを作成する

**Windows上で `build_exe.bat` をダブルクリック**します。必要なパッケージをインストールした後、PyInstallerでビルドします。初回はPython 3.11以降とインターネット接続が必要です。

次のファイルを同梱しています。

- `build_exe.bat`: 環境準備からビルドまで実行するバッチ
- `build_exe.py`: PyInstaller実行・サンプルの同梱・配布用ZIPの作成
- `OutlookMailDesk.spec`: onedir構成、コンソール非表示、アプリアイコン、COM関連モジュールの収集設定
- `hooks/hook-tkinterdnd2.py`: ドラッグ＆ドロップに必要なTclスクリプト・ネイティブライブラリの同梱設定
- `requirements-build.txt`: ビルド用依存パッケージ
- `bulk_mailer/assets/`: ウィンドウ・EXEに使うアプリアイコン

既存のPython環境から手動でビルドする場合:

```powershell
python -m pip install -r requirements-build.txt
python build_exe.py
```

ビルド結果は次の構成です。

```text
dist/
├─ OutlookMailDesk/
│  ├─ OutlookMailDesk.exe
│  ├─ _internal/           ← Python・ライブラリ・アセット
│  ├─ samples/
│  ├─ docs/                ← 画面画像・監査報告
│  └─ README.md
└─ OutlookMailDesk-windows-onedir.zip
```

`OutlookMailDesk-windows-onedir.zip` を配布し、展開後に `OutlookMailDesk.exe` を起動します。**EXEと `_internal` を含むフォルダー全体を配布してください。** 配布先へのPythonのインストールは不要で、従来版Outlookと設定済みのメールアカウントは必要です。

設定と処理記録は引き続き `%LOCALAPPDATA%\OutlookBulkMailer` に保存します。EXEの配置フォルダーには保存しません。Windows用EXEの作成はWindows上で行い、Linuxからのクロスビルドはしません。

## 初期設定

「設定」タブで次を指定し、「設定を保存して反映」を押します。

- **共通の件名**: 全員同じ件名です。未定の間は空欄で保存でき、本文のプレビューも利用できます。下書き作成・送信前には件名の入力が必要です。
- **社員情報CSV**: 1行目を見出し、2行目以降を社員情報として読み込みます。**A列＝スタッフID、B列＝社員ID（見出し「派遣元スタッフコード」）、C列＝氏名、J列＝メールアドレス**です。B1は「派遣元スタッフコード」にしてください。**取り込み・保存・確認画面に使うのは、この4項目だけ**です。D〜I列、K列以降は取り込み対象外です。IDは文字列として保持し、先頭の0を削除しません。
- **共通のCC**: 全メールに適用します。改行、カンマ、セミコロンで複数のメールアドレスを区切れます。空欄も可能です。
- **実行方法**: 初期値は「下書きに保存」です。「送信する」に変更すると確認後に送信を要求します。
- **本文テンプレート**: `{氏名}` などの記号に取り込みデータを差し込みます。差し込み項目は青文字・淡い青の背景で表示し、入力・貼り付け・項目挿入・元に戻す操作に合わせて更新します。色は編集画面だけの表示で、保存内容とメール本文はプレーンテキストです。画面に全項目の記号を表示しています。通常の波括弧を表示したい場合は `{{` と `}}` を使います。`{{氏名}}` は通常の文字として扱い、色を付けません。

氏名の照合では、全角・半角の違いと空白の違いを吸収します。宛先が未登録、または氏名が重複して宛先が確定できない場合は、対象一覧に表示します。必要なメールアドレスを個別編集で指定するか、CSVを直して読み込み直し、設定を保存してください。

CSVの読み込み成功時に、4項目を**その場で `contacts.json` に保存**します。次回起動はJSONから復元するため、元のCSVを移動・削除しても利用できます。**CSVを読み込み直すと全件置換**され、前のCSVにしかなかった社員は残りません。形式不正・列不足・氏名空欄・メールアドレス不正・保存失敗の場合は、以前のJSONと社員情報を保持します。不要列にしかデータがない行は読み飛ばします。

「社員情報を確認」で、スタッフID・社員ID・氏名・メールアドレスの4列の一覧を開きます。社員情報は1人1行のコンパクトな高さで表示し、列見出しは「社員ID」とします。長い値は横スクロールで確認できます。氏名が重複する行は着色します。**IDは保存・確認用で、宛先照合には氏名とメールアドレスだけを使用**します。

社員情報JSONの保存と、件名・CCなどの設定保存は別です。読み込み後は「設定を保存して反映」で未実行メールへ反映し、内容を確認してください。設定を保存せず終了しても、読み込み済みの社員情報JSONは保存されています。CSVを後から編集しただけではJSONは変わらず、明示的な再読み込みが必要です。

CSVはカンマ区切りで、UTF-8（BOMあり・なし）、UTF-16（BOMあり）、CP932に対応します。旧版の宛先JSONも読み込めますが、スタッフIDと社員IDは空欄です。社員情報CSVを読み込むと4項目のJSONへ全件置換します。移行用に従来のA列氏名・B列メールアドレスの `.xlsx` 読み込みも残しています。旧版で元ファイルのパスだけが保存されている場合は、一度読み込んでJSONに移行します。壊れたJSONは元CSVやExcelへ自動で戻さずエラーを表示するため、明示的に読み込み直してください。

`samples/社員情報サンプル.csv` と `samples/入力サンプル.txt` を使って試せます。サンプルのID・氏名・メールアドレスは例示用です。

## 入力テキスト

次の並びを1人分として繰り返します。先頭の空白行は取り除きます。各項目は1行で、必須項目間には空白行を1行だけ入れます。受入期間の次に「会社名」、その次に「事業所名」を記載します。「契約承認状態」の直後の不要行には空白行を挟みません。

```text
管理番号

2026/11/01 - 2027/03/31

会社名

事業所名

部署名

業務名

チーム名

氏名

派遣元

契約承認状態
不要行

不要行

次の人の管理番号
```

2つの不要行は読み飛ばします。**最後の人に限り、「契約承認状態」まで読めれば、その後の不要行・空白行が途中で切れていても、全くなくても読み込めます。** たとえば末尾が契約承認状態の行で終わる、または1つ目の不要行で終わる形式も有効です。

途中の人には、2つの不要行とその間の空白行、および次の人との区切りが必要です。会社名を含む契約承認状態までの必須項目が不足している場合は、最後の人でもエラーとします。日付や空白行の位置が不正な場合は、行番号の目安を表示して入力全体の修正を求めます。一部を黙って取り込むことはありません。

会社名は一覧の「取り込み情報」で確認でき、本文テンプレートへ `{会社名}` として差し込めます。初期の本文テンプレートは従来の内容を使用します。

txtはUTF-8（BOMあり・なし）、UTF-16（BOMあり）、CP932に対応します。入力後、画面上でテキストを編集できます。

## ファイルのドラッグ＆ドロップ

エクスプローラーからアプリの画面へ、**1ファイルずつ**ドロップできます。読み込みボタンも引き続き利用できます。

- `.txt`: 入力欄へ読み込み、入力画面を開きます。既に入力がある場合は置き換えるか確認します。
- `.csv`: 社員情報としてA・B・C・J列の4項目を読み込み、JSONを全件置換して設定画面を開きます。「設定を保存して反映」で一覧へ反映してください。
- `.xlsx`: 旧版の氏名・メールアドレス対応表を読み込む移行用です。

拡張子の大文字・小文字は問いません。複数ファイルの同時ドロップ、フォルダー、その他の拡張子は受け付けません。下書き保存・送信の処理中はドロップできません。ドロップだけでメールの作成・送信は行わず、一覧作成と内容確認を経て実行します。

取り込みの上限はtxt 10MiB、貼り付け500万文字、社員情報CSV 100MiB・見出しを除き10万行、旧Excelの展開後サイズ100MiBです。超過時は途中まで取り込まず、分割を求めます。氏名・本文・宛先などの不正な制御文字は拒否します。

## 確認から実行まで

1. テキストを貼り付けるか「txtファイルを開く」を押すか、txtをドラッグ＆ドロップします。
2. 「作成対象リストを作る」を押します。
3. 2行表示の一覧で全件の管理番号、氏名・派遣元・宛先、受入期間、受入先情報を確認します。共通の件名・CCは表の上に表示します。必要な場合は「本文・取り込み情報を表示」で詳細を開きます。承認状態による自動除外はしません。
4. 着色された問題行を選ぶと、表の下に具体的な問題を表示します。「宛先・本文を編集」でTo・CC・本文を修正でき、共通件名は設定画面で変更します。
5. 対象外の行は「対象／除外」で除外します。
6. 全件の内容を確認したら「下書きを保存」または「対象メールを送信」を押し、最終ダイアログで件数と実行方法を確認して実行します。確認済みを付ける操作は不要です。

設定を保存すると、未実行メールの件名・CC・本文・宛先照合を更新します。個別編集した内容も更新されるため、一覧で内容を確認してください。

問題のあるメールが実行対象に残っている場合は、全体を開始せず修正を求めます。実行済み・結果不確定・履歴のあるメールの再実行防止は維持しています。

同じパスのCSVを読み直した場合も、設定の保存と内容の再確認が必要です。入力テキストを変更した場合は、対象リストを作り直すまで実行できません。

メールはプレーンテキストで1契約につき1通作成します。同じ氏名の契約が複数ある場合も管理番号ごとに別メールです。管理番号が重複する入力は修正が必要です。本文は指定のテンプレートをそのまま使い、Outlookの署名は自動付与しません。

## 実行結果と保存先

- 設定: `%LOCALAPPDATA%\OutlookBulkMailer\settings.json`
- 社員情報: `%LOCALAPPDATA%\OutlookBulkMailer\contacts.json`（社員ごとにスタッフID・社員ID・氏名・メールアドレスの4項目。元ファイルのパス・形式バージョンも記録、最大100MiB）
- 処理記録: `%LOCALAPPDATA%\OutlookBulkMailer\logs\*.jsonl`
- 入力した契約一覧と個別編集は、アプリ終了時には保存しません。

処理記録には実行日時（UTC）、管理番号、To、実行方法、処理状態、エラーを保存します。メール本文は保存しません。

「送信要求済み」はOutlookへの送信要求が完了した状態です。配信完了を保証する表示ではありません。Outlookがオフラインの場合などは送信トレイに残ることがあります。

途中でエラーが起きた場合は、その時点で停止します。完了した行と結果が不確定な行は再実行できません。未処理分だけを続けられます。結果が不確定なメールはOutlookの下書き・送信トレイ・送信済みと処理記録を確認してください。

リストの再作成・アプリ再起動後も、過去の処理記録を読み、**管理番号＋実行方法**が一致する行を「履歴あり」として対象から除外します。件名・本文・宛先を変えてもこの履歴は解除されません。「開始」の記録しか残っていない場合も結果不確定として扱います。下書き保存と送信は別の実行方法なので、下書き保存後に送信モードへ変えてリストを作り直すことはできます。

同じ処理記録フォルダーを使う複数起動間では、OSロックで実行を直列化します。別の実行が処理中なら、その場で停止します。履歴が壊れている・読めない場合も、新しいメールは作成・送信しません。

処理記録は再実行防止にも使うため、削除・移動しないでください。現在は履歴を解除するUIを設けていません。結果不確定な行を自動で再送する機能もありません。別のWindowsユーザーや別PCでは記録を共有しません。また、Outlookで手動送信した下書きの送信状態は追跡していません。

## 検証

```powershell
python -m unittest discover -s tests -v
```

テストでは入力の構造・日付・文字コード・Excel照合・本文・設定の保存・実行前の検証・途中エラー時の停止と処理記録を検証します。GUIでは、取り込み結果の表示、問題行だけの着色、修正後の解除、確認フラグなしの一括作成、対象除外、設定反映、モード表示、処理中の操作制限を検証します。GUIテストにはディスプレイが必要です。Outlookの保存・送信呼び分けはモックで確認します。

ネイティブライブラリの収集テストも実行する場合は、先に `python -m pip install -r requirements-build.txt` を実行してください。PyInstallerがない場合、この1件はスキップします。

開発環境はLinuxです。2行表示版ではサブエージェント3役で独立再監査を行いました。その171件に、社員情報CSV・4項目のJSON保存と復元・旧JSON互換・確認画面の追加14件を加え、計185件が成功しました。失敗・スキップはありません。CSV機能追加の検証は主担当が実施しています。[独立再監査報告](docs/REAUDIT_2026-10-17.md)と[最終監査報告](docs/FINAL_AUDIT.md)に検証範囲をまとめています。

Windows上のEXEビルド・起動、エクスプローラーからの実ドラッグ操作、WindowsでのOSロック、実際のOutlook COM連携は未検証です。導入時に対象WindowsでEXEをビルドし、ドラッグ読み込みと少数データの下書き保存・宛先解決を確認する必要があります。

画面プレビューの再作成には、Pillowと利用可能なディスプレイを用意し、`python tools/preview_ui.py` を実行します。サンプルデータと一時設定のみを使い、Outlook操作は無効にしています。
